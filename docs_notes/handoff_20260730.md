# Handoff: robustness campaign — what's left after July 30, 2026

Context for whoever picks this up: we're running a large robustness campaign on the SOE-Rubbo
model (does the Float/Managed/Peg welfare ranking survive across network structure, price
rigidity, and policy-rule choices). Full rationale and exact parameter grids are in the plan doc
`C:\Users\sugarkhuu\.claude\plans\noble-strolling-feather.md` (or ask Sugarkhuu to re-share it) —
this file is the short, practical "what to actually run, in order" version.

## What's already done (don't redo)
1. `open_economy_network_chile.mod` (and its `_managed`/`_peg`/`_cpiit`/`_ppiit` siblings) already
   have two new policy-rule options added: strict CPI-inflation-targeting (`cpi_it`) and strict
   PPI/domestic-inflation-targeting (`ppi_it`), alongside the original float/managed/peg. Verified
   this didn't break the existing three regimes.
2. The ψ-sensitivity-by-network-density sweep is done: `results/psi_netdens_regime_sweep.csv` has
   all 45 points (5 ψ values × 3 network densities × 3 regimes). Just needs to be turned into
   welfare numbers and read — nobody has looked at what it says yet.

## What to run next, in order

**Step 1 — Price rigidity sweeps.** Does the "Services absorbs most of the welfare cost" result
depend on exactly how sticky Services' prices are, and does that interact with the network?
- A script for the "scale every sector's stickiness together" version already exists
  (`code/sweep_rigidity_netdens_chile.m`) but has never been run — needs a driver shell script
  (copy the pattern in `code/drive_psi_netdens_sweep.sh`, swap in the rigidity function and a
  kappa grid of roughly 0.5/0.75/1.0/1.1/1.15) and then actually run it.
- Still need to write a second version that moves ONLY the Services sector's stickiness (not all
  three at once) — this is the one that most directly answers Christian's original comment.
- Roughly 100 solves total, ~25-30 seconds each.

**Step 2 — Does the risk-premium shock size and the ψ parameter reinforce each other?** Small
add-on: 9 runs, Peg regime only, varying both at once. Nothing built for this yet.

**Step 3 — Try different-shaped trade networks, not just "more or less network."** Right now every
sweep varies one dial (how dense the network is) on one triangular-shaped network. Build two more
network shapes (one where Manufacturing is the hub everyone trades through; one where trade flows
in a straight line Resource→Manufacturing→Services) and re-check whether the Services story and the
optimal-policy-weight result still hold. Nothing built for this yet, ~50-60 solves.

**Step 4 — Try the new policy rules from Step "already done" #1.** The model options exist
(cpi_it, ppi_it) but nobody has actually run the sweep comparing them to float/managed/peg yet, or
tried turning off the FX-response weight entirely (strict inflation targeting), or tried different
combinations of how much the central bank cares about inflation vs. the output gap. ~20 solves.

**Step 5 — Once all the above CSVs exist, someone needs to turn them into readable tables/plots**
and update the project's own notes (`docs_notes/results_summary.md`,
`docs_notes/calibration.md`) — those files describe what's been found so far and are the source of
truth for the eventual paper. Also: `docs_notes/paper_context.md` currently says the ψ-sensitivity
check "hasn't been built yet" — that's now out of date and should be corrected.

## Bottom line for a non-technical read
About 45 of roughly 280 total test runs are done (the ψ-vs-network-density ones). The rest — price
stickiness, alternative trade-network shapes, and alternative central-bank rules — haven't been run
yet. Each batch takes on the order of an hour or two of computer time once someone sits down to
write/run the remaining scripts; the pattern to follow for each one is already established from the
first batch, so it's mostly repetition, not new design work.
